## パッケージ版ベータ

開発者ではなく、ベータ版を試したい場合は、パッケージ版を使うのが最も簡単です。こちらをご覧ください。

https://betas.ankiweb.net/

## ビルド済み Python wheel

ビルド済みの Python パッケージは PyPI から入手できます。次の用途に便利です。

- 自分でビルドせず、ローカルの Python 環境から Anki を実行する
- アドオン開発でコード補完を使う
- Anki の Python ライブラリを介して `.anki2` ファイルを変更するコマンドラインスクリプトを作成する

64 ビット版の Python 3.10 以降をインストールする必要があります。Python は python.org または使用中のディストリビューションからインストールできます。

詳しくは https://betas.ankiweb.net/#via-pypipip をご覧ください。手順内の `--pre` は、pip にアルファ版・ベータ版を取得させるオプションです。`--pre` を外すと、最新の安定版がダウンロードされます。

## ソースからビルドする

任意のフォルダーに Git リポジトリをクローンします。パスにスペースを含めないでください。Windows の場合は、パスを短くすることをおすすめします。

すべてのプラットフォームで、次のソフトウェアが必要です。

- Rustup（https://rustup.rs/）。`rust-toolchain.toml` で指定された Rust バージョンが未インストールの場合、自動でダウンロードされます。このファイルを削除してディストリビューション提供の Rust を使う場合、新しいバージョンではビルドできてもテストに失敗することがあり、古いバージョンはまったく動作しない可能性があります。
- N2 または Ninja。N2 の方が状態を詳しく表示します。`tools/install-n2`、または Windows では `bash tools\install-n2` でインストールできます。Ninja を使う場合は、[こちら](https://github.com/ninja-build/ninja/releases/tag/v1.11.1)からダウンロードして PATH に追加するか、バージョン 1.10 以降をディストリビューションや Homebrew からインストールしてください。
    - Windows に WSL がインストールされている場合、MSYS2 bash と競合することがあります。エラーが発生する場合は、代わりに `C:\msys64\usr\bin\bash.exe tools/install-n2` を実行してください。
- （任意）[just](https://just.systems/man/en/packages.html) コマンドランナー。`brew install just` または `uv tool install rust-just` でインストールします。Anki 固有のコマンドを実行する公式ツールとして `just` を試験的に導入しており、将来的には正式な標準になる見込みです。

プラットフォーム固有の要件:

- [Windows](/developers/windows)
- [Mac](/developers/mac)
- [Linux](/developers/linux)

## 開発中に Anki を実行する

Anki のソースフォルダーのルートから次を実行します。

```
./run
```

（Windows では `.\run`）

Anki をビルドし、その場で実行します。

初回のビルドでは、複数の依存関係をダウンロードしてビルドするため、時間がかかります。ビルドが完了すると、Anki が自動で起動します。

Anki が起動しない場合は、[追加ライブラリ](/manual/platform/linux/missing-libraries)のインストールが必要なことがあります。

## テストとチェックを実行する

すべてのテストを一度に実行するには、プロジェクトのルートで次を実行します。

```
./ninja check
```

（Windows では `tools\ninja check`。）

特定のチェックだけを実行することもできます。たとえば、チェック中に `check:svelte:editor` が失敗した場合は、`./ninja check:svelte:editor` でそのチェックを再実行するか、`./ninja check:svelte` ですべての Svelte チェックを実行できます。

## フォーマットを修正する

フォーマットの問題が報告された場合は、次を実行して修正できます。

```
./ninja format
```

## Ruff、ESLint、著作権ヘッダーの問題を修正する

```
./ninja fix
```

## Clippy の問題を修正する

```
cargo clippy --fix
```

## 自分の未追跡ファイルをフォーマットとチェックから除外する

バージョン管理の対象外にし、フォーマッターやチェックで処理しないファイルやフォルダーをプロジェクトに追加したい場合は、`extra` フォルダーに入れてください。自動的に無視されます。

## 最適化ビルド

既定では、`./run` は最適化されていないビルドを作成します。コンパイルは速くなりますが、Anki の実行速度は遅くなります。

最適化モードで Anki を実行するには、次を使います。

```
./tools/runopt
```

または `RELEASE=1` または `RELEASE=2` を設定します。後者はさらに最適化しますが、ビルドにかかる時間も大幅に長くなります。

## 再配布可能な wheel をビルドする

プラットフォーム別の手順で説明した `./run` は、ビルドフォルダーから Anki を直接起動する簡易方法です。通常の学習には、Python wheel をビルドし、自分の Python 仮想環境にインストールすることをおすすめします。Anki のビルドプロセスで使われない追加ツールを PyPI からインストールする場合にも適しています。

Mac/Linux で wheel をビルドするには、次を実行します。

```
./tools/build
```

（Windows では `.\tools\build.bat`。）

生成された wheel は `out/wheels` にあります。パスを `pip install` コマンドに指定してインストールできます。

[ベータサイトの手順](https://betas.ankiweb.net/#via-pypipip)に従い、`pip install --upgrade --pre aqt` の代わりに次のようなコマンドを使います。

```
/my/pyenv/bin/pip install --upgrade out/wheels/*.whl
```

（Windows ではワイルドカードを使わず、ファイル名を1つずつ指定してください。）

## ビルドファイルを削除する

サブモジュールのチェックアウトを除き、ほとんどのビルドファイルは `out/` フォルダー（Windows では `node_modules` も）に保存されます。クリーンビルドを行う場合や空き容量を増やす場合は、このフォルダーを削除できます。

Cargo、Yarn、pip は、同じシステム上のほかのビルドでも使う共有キャッシュに依存関係を保存します。キャッシュを削除する場合は、`~/.rustup`、`~/.cargo`、`~/.cache/{yarn,pip}` を確認してください。Windows の Yarn キャッシュは `%LOCALAPPDATA%\Yarn` にあります。

ビルドスクリプトを使わずに Rust を実行する（例: cargo や Rust Analyzer を使う）場合、既定の出力先を変更していなければ、生成ファイルは `target/` に保存されます。

## ストレージとパフォーマンス

多くのエディターは Rust のサポートに rust-analyzer を使います。ファイルを保存するたびに `cargo check` がバックグラウンドで実行されるため、ビルド前に問題を確認できます。便利ですが、性能の低いマシンではディスク使用量や CPU 負荷が目立って増えることがあります。その場合は、「保存時にチェック」を無効にすることを検討してください（例: VS Code で `rust-analyzer.checkOnSave` を `false` に設定）。リアルタイムのエラーチェックは使えなくなりますが、コード補完や定義への移動などには引き続き rust-analyzer を使えます。

「保存時にチェック」を無効にし、cargo コマンドも手動で実行しない場合は、使用されなくなった `target/` フォルダーを削除できます。

ドキュメントサイトをビルドして表示するには、次を実行します。

```

```

```

```

## 環境変数

Anki の起動前に `ANKIDEV` を設定すると、標準出力に追加のログメッセージが表示され、自動バックアップが無効になります。テスト用のプロファイル以外では使わないでください。`./run` を使うと自動で有効になります。

`TRACESQL` を設定すると、すべての SQL 文が実行時に表示されます。

Anki の起動前に `LOGTERM` を設定すると、通常は `collection2.log` に記録される警告とエラーも標準出力に表示されます。

`ANKI_PROFILE_CODE` を設定すると、終了時に Python のプロファイリングデータが書き出されます。

## インストーラー

インストーラーをビルドするには、`tools/build-installer` を実行します。

OS に応じて、`out/installer/dist` に次のファイルが生成されます。

- Windows 用 MSI インストーラー
- macOS 用 `.dmg` ファイル
- Linux 用 tarball

### ビルド中に問題が発生した場合

インストーラーのビルドで問題が起きた場合は、すべての依存関係がインストールされているか確認してください。詳しくは[ソースからビルドする](./#building-from-source)をご覧ください。

# 開発と学習を分ける

開発時に使う別のプロファイルを「ファイル」>「プロファイルを切り替える」から作成できます。Anki の起動時に `-p [プロファイル名]` を指定すると、特定のプロファイルを読み込めます。

PyCharm を使う場合:

- PyCharm の Anki フォルダーのルートにある `run` ファイルを右クリックします。
- 「Edit 'run'...」をクリックし、「Script options」に `-p [開発用プロファイル名]` を引用符なしで入力します。
- 「OK」をクリックします。
