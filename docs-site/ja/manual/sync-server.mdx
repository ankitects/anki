AnkiWebを使えない、または使いたくない上級者は、自分で運用する同期サーバーを利用できます。

次の点に注意してください。

- これは、ネットワークやコマンドラインの操作に慣れた人向けの高度な機能です。設定、ネットワーク、ファイアウォールに関する問題は自分で解決できることが前提です。利用はすべて自己責任です。
- 新しいクライアントは同期プロトコルの変更に依存することがあります。Ankiクライアントだけ更新し、サーバーを更新しないと、同期できなくなる場合があります。
- サードパーティ製の同期サーバーもありますが、動作確認は行っていません。同期プロトコルの変更への対応に時間がかかる傾向があるため、推奨しません。
- カスタムサーバーを設定しても、Anki内のメッセージでは「AnkiWeb」という表記が使われます。たとえばサーバーが停止している場合も「AnkiWebに接続できません」と表示されます。

## インストールと起動

サーバーのインストール方法と起動方法はいくつかあります。次のいずれかを利用できます。

- Ankiデスクトップ版に同梱されている同期サーバー
- AnkiのGUI依存関係を含まない、独立した軽量同期サーバー。Python版とRust版があります。

### 配布版を使う

Anki 2.1.57以降のデスクトップ版に組み込まれた同期サーバーを使います。

Windowsのcmd.exeでは、次のように実行します。

```
set SYNC_USER1=user:pass
"\Program Files\anki\anki-console" --syncserver
```

MacOSのTerminal.appでは、次のように実行します。

```
SYNC_USER1=user:pass /Applications/Anki.app/Contents/MacOS/anki --syncserver
```

<Note>Anki 25.07から25.09.4では、ankiをlauncherに置き換えてください。</Note>

Linuxでは次のように実行します。

```
SYNC_USER1=user:pass anki --syncserver
```

### Pipを使う

デスクトップ版AnkiのGUI依存関係をダウンロードせずに済むよう、PyPIから取得したPythonパッケージで独立した同期サーバーを実行できます。Python 3.9以降をインストールしてください。

```
python3 -m venv ~/syncserver
~/syncserver/bin/pip install anki
SYNC_USER1=user:pass ~/syncserver/bin/python -m anki.syncserver
```

### Cargoを使う

Anki 2.1.66以降では、次のコマンドで独立した同期サーバーのRust実装をビルドできます。Rustupをインストールしてください。

```
cargo install --locked --git https://github.com/ankitects/anki.git --tag 25.02.5 anki-sync-server
```

25.02.5は、利用するAnkiの最新バージョンに置き換えてください。

Protobuf（protoc）をインストールする必要があります。

ビルド後、次のように起動できます。

```
SYNC_USER1=user:pass anki-sync-server
```

### ソースコードをチェックアウトして使う

GitHubからAnkiリポジトリをクローンした場合は、次のコマンドでインストールできます。

```
./ninja extract:protoc ftl_repo
cargo install --path rslib/sync
```

### Dockerを使う

ユーザーが作成したDockerfileと手順は[こちら](https://github.com/ankitects/anki/tree/main/docs/syncserver)にあります。

## 複数のユーザー

SYNC_USER1で1人目のユーザー名とパスワードを指定します。これは必須です。複数のアカウントを設定する場合は、SYNC_USER2、SYNC_USER3なども指定できます。

## ハッシュ化したパスワード

上級者は、平文の代わりにハッシュ化したパスワードを使えます。パスワードハッシュを生成するには、[こちらのツール](https://git.sr.ht/~laalsaas/pbkdf2-password-hash)など、別のツールが必要です。環境変数PASSWORDS_HASHEDに1（またはほかの値）を設定すると、サーバーがハッシュ化されたパスワードを使うようになります。

ハッシュ化したパスワードを使う場合、SYNC_USER変数は「ユーザー名:パスワードハッシュ」の形式にします。パスワードハッシュはPHC形式で指定してください。

## 保存場所

サーバーはコレクションとメディアのコピーをフォルダーに保存します。初期設定では~/.syncserverです。SYNC_BASE環境変数を定義すると、保存先を変更できます。

- 通常のAnkiデータフォルダーと同じ場所にしないでください。サーバーとクライアントは、それぞれ別のコピーを保存する必要があります。
- ファイルをサーバーフォルダーへ手動でコピーせず、サーバーに同期してください。

## インターネットからのアクセス

サーバーは暗号化されていないHTTP接続で待ち受けます。そのため、インターネットに直接公開するのはおすすめできません。ローカルネットワーク内だけで使うか、VPN（Tailscaleは設定が簡単とされています）やHTTPSリバースプロキシなどで通信を暗号化してください。

サーバーが接続を受け付けるホストとポートは、SYNC_HOSTとSYNC_PORTで変更できます。

## クライアントの設定

### サーバーのURL

コンピューターのネットワークIPアドレスを調べ、各Ankiクライアントの接続先に設定します。たとえばhttp://192.168.1.200:8080/のようなURLです。URLは設定画面で指定できます。

AnkiMobileからローカルネットワーク上のサーバーに接続できない場合は、iOSの設定を開き、画面下部にあるAnkiを選んで、「ローカルネットワーク」へのアクセスをオフにしてからオンに戻してください。

古いデスクトップクライアントでは、SYNC_ENDPOINTとSYNC_ENDPOINT_MEDIAを指定する必要があります。たとえば、それぞれhttp://192.168.1.200:8080/sync/とhttp://192.168.1.200:8080/msync/です。AnkiDroid 2.16より前のクライアントでは、2つのエンドポイントを別々に設定します。

### 認証情報

同期するには、SYNC_USER1などのユーザー認証情報を設定画面の**AnkiWebアカウント**欄に入力します。

## リバースプロキシ

nginxなどのリバースプロキシでHTTPS接続を提供し、サブパス（例：http://example.com/custom/からhttp://localhost:8080/への転送）にバインドする場合、Ankiの設定URLの末尾にスラッシュを付けてください。http://example.com/customのようにスラッシュを省くと動作しません。

Caddyを使う場合、メディアファイルのダウンロード時に接続の問題が起きないよう、[HTTP読み取りバッファーのサイズ](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy#read_buffer)を大きくしてください。

```caddyfile
reverse_proxy http://127.0.0.1:8080 {
	transport http {
		read_buffer 512k
	}
}
```

iOSはTLS 1.3に対応していません。リバースプロキシでTLS 1.2を有効にしてください。有効でないと「error code -9836」が表示されます。

## 大きなリクエスト

初期設定では、AnkiWebと同じアップロード上限が適用されます。上限を増やす場合は、MAX_SYNC_PAYLOAD_MEGSを100より大きい値に設定できます。リバースプロキシを使っている場合は、そちらの上限も変更が必要なことがあります。

## 変更の提案

このサーバーはAnkiに同梱されているため、設計ではシンプルさを重視しています。個人や家族での利用を想定しており、REST APIや外部データベースなどを追加するPRは、現時点では採用されにくいでしょう。判断に迷う場合は、PRの作業を始める前に相談してください。

既存のAPIを探している場合は、AnkiConnectアドオンが用途に合うかもしれません。
