## 基本的な使い方

基本的な使い方は[開発ガイド](./development)で説明しています。

## アーキテクチャ

`build/` フォルダーは4つのパッケージで構成されています。

- `build/configure` はビルドグラフのアクションと入出力を定義します。ビルド手順を追加または変更する場合は、ここを編集します。定義されたアクションはビルド時に `build.ninja` ファイルへ変換され、Ninja が実行します。
- `build/ninja_gen` は `build.ninja` ファイルを生成するライブラリです。「Rust クレートをビルドする」「コマンドを実行する」などのルールも含みます。
- `build/archives` は、ビルドプロセスの一環として依存関係をダウンロード、チェックサム検証、展開するヘルパーです。
- `build/runner` は複数の役割を担います。
    - ビルドファイルを生成して Ninja を呼び出す、ビルドプロセスのエントリーポイントです。
    - ビルドファイル内の実行ファイルの呼び出しをラップし、正常終了した場合は出力を表示しません。
    - Windows の違いなど、クロスプラットフォームで簡単に記述できない複数段階の処理に使うヘルパーを提供します。

## ビルドの問題を調べる

ビルドプロセスで問題が起きた場合:

- `./ninja pylib -v` などを使うと、実行されたコマンドを確認できます。
- `N2_OUTPUT_SUCCESS=1` を設定すると、正常終了したコマンドの出力を確認できます。
- `./ninja qt/anki -d explain` などを使うと、ターゲットの再ビルドが発生した理由を確認できます。
- `./ninja -- -t browse wheels` などを使うと、ビルドグラフを確認できます。
- ビルドのパフォーマンスは[こちら](https://discourse.cmake.org/t/profiling-build-performance/2443/3)を参考にプロファイルできます。
