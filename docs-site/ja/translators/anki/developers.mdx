Anki のコードベースにユーザー向けの文字列を追加する場合、翻訳できるようにするための作業が別途必要です。

Anki のコードベースでは最近、旧 gettext システムからの移行が行われ、現在は Fluent の `col.tr` と `aqt.utils.tr` のみを使用しています。

まず[core のドキュメント](./core)を確認し、文字列が翻訳者にどのように表示されるかを見てください。翻訳者には、文字列がコードのどこで使われているか分かりません。そのため、何を翻訳するのか理解してもらうために、コメントが必要になることがよくあります。

## 新しい文字列を追加する

例として、「アドオンが x 個あります」という文字列を追加するとします。

コードベースに翻訳可能な文字列を追加するには、まず `core` モジュール（すべての Anki クライアントで使われる可能性が高いテキスト）と、パソコン版固有の `desktop` モジュールのどちらに属するかを判断します。アドオンはパソコン版でのみサポートされるため、この例では `desktop` モジュールを使います。

- 英語の `core` ファイルは `ftl/core` にあります。
- 英語の `desktop` ファイルは `ftl/qt` にあります。

`ftl/qt/addons.ftl` のようなファイルを探し、適切なファイルがなければ作成します。その後、ファイルに文字列を追加します。

各文字列には、一意のキーが必要です。ファイル名と同じテキストで始め、ハイフンで区切った単語を少なくともいくつか含めてください。たとえば、次のように追加します。

```properties
addons-you-have-count = You have { $count } add-ons.
```

`count` が5の場合、文字列は「You have 5 add-ons.」になります。`count` が1の場合は「You have 1 add-ons.」となり、不自然です。そのため、単数形の場合の文字列も追加する必要があります。

```properties
addons-you-have-count = You have { $count ->
    [one] 1 add-on
   *[other] {$count} add-ons
   }.
```

上の記述では、単数形の場合に最初の文字列を使い、それ以外の場合は2番目の文字列を使うよう Fluent に指示しています。

これで改善されますが、数によって「you have」にあたる部分も変わる言語では、翻訳が難しくなることがあります。そのため、記述は長くなりますが、可能な場合は選択肢ごとに文全体を列挙する方が適切です。

```properties
addons-you-have-count = { $count ->
    [one] You have { $count } add-on.
   *[other] You have { $count } add-ons.
   }
```

こうすると、翻訳者が自然な文の構造で訳せるよう、最も大きな裁量を残せます。

単数形の場合にも変数を使っている点に注目してください。英語では単数形の `$count` は常に1ですが、ほかの言語では21など、別の数にも単数形が使われることがあります。翻訳者が `1` を `{ $count }` に置き換えることもできますが、その必要に気づかない場合があります。変数を使っておくと、こうした間違いを減らせます。

`.ftl` ファイルにある文字列の大半は、旧 gettext システムから取り込まれたものです。そのため、ベストプラクティスに沿っていないものも多くあります。また、旧システムでは次のような書き方が使われていました。

```python
msg = "%s %d %s" % (_("Studied"), card_count, _("today"))
```

このように Python で文字列を組み立てるのは避けてください。翻訳が難しくなり、英語のように単語間にスペースを使わない言語もあるためです。この例では、個数を引数に取る単一の翻訳可能な文字列にする方が適切です。

最後に、翻訳者向けのコメントを1つ以上追加します。

```properties
### 3つのシャープ記号で始まる行は、ファイル内のすべての文字列について
### 翻訳システムに表示されます。
### ファイル全体の概要を記載できます。必要のないファイルもあります。

## 2つのシャープ記号で始まる行は、次の文字列すべてに表示されます。
## 別の2つのシャープ記号が現れるか、ファイル末尾に達すると終了します。

# このコメントは次の文字列だけに適用されます。例:
# アドオン管理画面（ツール > アドオン）のタイトルバーに表示される。
addons-you-have-count = { $count ->
    [one] You have { $count } add-on.
   *[other] You have { $count } add-ons.
   }
```

## 新しい文字列を使う

`.ftl` ファイルに文字列を1つ以上追加したら、通常どおりソースツリーから Anki を実行します。新しい文字列がコンパイルされ、Python、TypeScript、Rust から利用できるようになります。

### Python

文字列を取得するには、次のコードを使います。

```python
from aqt.utils import tr

msg = tr.addons_you_have_count(count=3)
```

- ビルドプロセスで、適切な引数を持つ `snake_case()` 関数が自動生成されます。存在しない文字列を使ったり、引数を省略したり、誤った引数を渡したりしていないか、テストで確認されます。
- 生成された関数の docstring には `.ftl` ファイルにある原文が記載されます。PyCharm などのエディターでは、関数にカーソルを合わせると表示される文字列を確認できます。
- `qt/` のコードでは `aqt.utils.tr()` を使えますが、`pylib` のコードでは `col.tr()` を使ってください。

Python の REPL で文字列を試す場合は、先に `set_lang()` を呼び出してください。

```python
>>> from anki.lang import set_lang
>>> from aqt.utils import tr
>>> set_lang("en", "")
>>> tr.addons_you_have_count(count=3)
'You have \u20683\u2069 add-ons.'
```

挿入された Unicode 文字に注目してください。これにより、左から右に書く言語と右から左に書く言語が混在しても、テキストが正しい順序で表示されます。デバッグ時には、次のようにこれらの文字を取り除けます。

```python
>>> from anki.lang import without_unicode_isolation as nosep
>>> nosep(addons_you_have_count(count=3))
'You have 3 add-ons.'
>>> nosep(addons_you_have_count(count=1))
'You have 1 add-on.'
```

### TypeScript

自動生成された関数を含むグローバルオブジェクトが、camelCaps 形式で利用できます。例:

```typescript
import * as tr from "../lib/ftl";

console.log(tr.statisticsCardsPerDay({ count: 5 }));
```

関数の docstring には原文が記載されているため、カーソルを合わせるとテキストを確認できます。

翻訳を使うには、まずバックエンドから取得する必要があります。次のように、含めるモジュールを指定してください。

```typescript
import { setupI18n, ModuleName } from "../lib/i18n";

await setupI18n({ modules: [ModuleName.STATISTICS] });
```

### Rust

バックエンドとコレクションの構造体には `.tr` に I18n オブジェクトがあり、これを呼び出して翻訳を取得できます。たとえば、Collection のメソッドでは次のようにします。

```rust
println!("{}", self.tr.database_check_missing_templates(5))
```

docstring には原文が記載されており、エディターで各引数の名前を確認できます。

戻り値は `Cow` です。`String` が必要な場合は、`.to_string()` または `.into()` を呼び出します。

### 旧形式

Anki 2.1.44 より前のバージョンでは、代わりに単一の関数と別の定数を使っていました。たとえば、次のコードではなく

```python
from aqt.utils import tr

msg = tr.addons_you_have_count(count=3)
```

次のように記述していました。

```python
from aqt.utils import tr, TR

msg = tr(TR.ADDONS_YOU_HAVE_COUNT, count=3)
```

この旧形式は現在も使えますが、今後削除される予定です。

## 繰り返し使う内容

複数の翻訳で同じテキストを共有する必要がある場合があります。たとえば検索コードには、次のように個別のエラーメッセージが複数あります。

```properties
search-invalid-added = Invalid search: 'added:' must be followed by a positive number of days.
search-invalid-edited = Invalid search: 'edited:' must be followed by a positive number of days.
```

同じ接頭辞を持つメッセージが多いため、接頭辞を別の文字列に分けられます。

```properties
search-invalid-search = Invalid search: { $reason }
search-invalid-added = 'added:' must be followed by a positive number reason.
search-invalid-edited = 'edited:' must be followed by a positive number of days.
```

その後、コードで2つの項目からメッセージを組み立てます。外側の文字列に Fluent 変数を使っている点に注目してください。言語によっては理由を先に置いたり、コロンの後にスペースを入れなかったりするためです。

## 可能な限り HTML を避ける

翻訳者が開発経験を持っているとは限らず、HTML は読みにくく、正しく翻訳するのが難しい場合があります。可能であればプレーンテキストを使ってください。HTML が必要な場合や、使うと明確になる場合は、代わりに Markdown を検討してください（例は検索の翻訳を参照してください）。

## 変更される可能性のある文字列を避ける

将来変わる可能性がある選択肢の一覧などを、1つの文字列に列挙するのは避けてください。文字列を後で更新するとき（更新を忘れなかった場合）、翻訳者が変更に気づくよう、新しい ID を割り当てる必要があります。そうすると、翻訳者が更新するまで既存の翻訳がすべて無効になります。更新には数か月、ときには数年かかることもあります。

## 文字列を増やしすぎない

新しい文字列の追加は必要な範囲にとどめてください。翻訳者の時間は貴重です。Anki に含まれる文字列が増えるほど、翻訳作業の負担も大きくなります。ほとんどの人が遭遇しないようなまれなエラーのメッセージは、翻訳する必要がないかもしれません。

## アドオン

アドオンでは Anki の既存の文字列を利用できますが、新しい文字列を追加する場合は、Anki 本体ではなくアドオンに追加する必要があります。アドオンの翻訳方法は自由に選べます。

- 翻訳を行わない場合は、通常の文字列を使うのが最も簡単です。
- 次に簡単な方法は、すべての文字列を辞書または Python モジュールに置き、新しい言語を追加するプルリクエストを受け付けることです。`anki.lang.currentLang` の値を確認して、適切な辞書を選べます。
- 適切な複数形のサポートが必要な場合は gettext を検討してください。ただし、上記の方法よりかなり複雑です。ソースから文字列を抽出し、コンパイル済みの文字列を生成するためのビルド手順が別途必要です。完成した `.po` ファイルを翻訳者からメールで受け取るか、プルリクエストを送ってもらえます。Launchpad や Crowdin など、gettext に対応するオンライン翻訳サービスもありますが、ファイルのアップロードとダウンロードを手動で行うか、設定用のスクリプトを作成する必要があります。

現在、アドオンに Fluent を使うことは推奨していません。対応するツールが限られており、Fluent の Python ライブラリをアドオンに同梱する必要があるためです。
