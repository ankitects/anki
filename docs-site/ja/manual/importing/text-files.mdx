---
title: "テキストファイル"
---

カンマ、セミコロン、タブでフィールドが区切られた**プレーンテキスト**ファイルは、いくつかの条件を満たせば Anki にインポートできます。

- ファイルはプレーンテキスト（`myfile.txt`）である必要があります。`myfile.xls`、`myfile.rtf`、`myfile.doc` などの形式は、事前にプレーンテキストファイルとして保存してください。
- ファイルは UTF-8 形式である必要があります（後述）。
- Anki は、最初の（コメントではない）行を見てファイル内のフィールド数を判定します。後続のレコードのフィールド数が少ない場合、不足分は空欄として扱われます。フィールド数が多い場合、余分な内容はインポートされません。
- Anki はファイルのフィールド区切り文字（カンマ、タブなど）を推測します。推測が間違っている場合は、インポートオプション画面で変更し、結果をプレビューできます。または、特定の区切り文字を指定するために[ファイルヘッダー](./#file-headers)を追加します。

テキストファイルのフィールドは、タグフィールドも含め、ノートの任意のフィールドに割り当てられます。インポート時に、テキストファイル内の各フィールドとノート内のフィールドの対応を選択できます。

テキストファイルのインポート時に、カードを追加するデッキを選択できます。ただし、テンプレートのいずれかでデッキ上書きが設定されている場合は、選択したデッキではなく、上書き先のデッキにカードが入ります。

次は、3つのフィールドがあるファイルの例です。

```text
    apple;banana;grape
    first field;second field;third field
```

フィールド内に改行または区切り文字を含める方法は2つあります。

**フィールドの内容を引用符で囲み、文字をエスケープする:**

```text
    hello;"this is
    a two line answer"
    two;this is a one line field
    "this includes a ; (semicolon)";another field
```

引用符はフィールドの開始位置と終了位置を示すため、フィールド内に引用符を含める場合は、二重引用符1つを二重引用符2つに置き換えて通常の処理から「エスケープ」します。

```text
    field one;"field two with ""escaped quotes"" inside it"
```

LibreOffice などの表計算ソフトで CSV ファイルを作成すると、二重引用符は自動的にエスケープされます。

**HTML の改行を使う:**

```text
    hello; this is<br>a two line answer
    two; this is a one line one
```

HTML の改行を機能させるには、インポートダイアログで **Allow HTML in fields** を有効にしてください。

複数行にわたる穴埋め削除を使う場合、エスケープした複数行のテキストは正しく動作しません。この場合は HTML の改行を使ってください。

別のフィールドにタグを含め、そのフィールドをインポートダイアログでタグフィールドとして指定することもできます。

```text
    first field;second field;tags
```

次は、最初の行が無視される（`#`）ファイルの例です。

```text
    # this is a comment and is ignored
    foo bar;bar baz;baz quux
    field1;field2;field3
```

## スプレッドシートと UTF-8

ファイルにアクセント付き文字や日本語など、ラテン文字以外の文字が含まれる場合、Anki ではファイルを「UTF-8 エンコーディング」で保存する必要があります。Excel よりも、無料の LibreOffice 表計算ソフトを使う方法が簡単です。UTF-8 に簡単に対応し、Excel とは異なり、複数行の内容も正しく書き出せます。Excel を使い続ける場合は、[こちらのドキュメント](https://docs.google.com/document/d/12YE_FS6A9ANLTESJNtPP116ti4nNmCBghyoJBRtno_k/edit?usp=sharing)をご覧ください。

LibreOffice で Anki が読み込めるファイルとして保存するには、**File > Save As** を選び、ファイル形式に CSV を指定します。既定のオプションを確定するとファイルが保存され、Anki にインポートできます。

## HTML

Anki は、テキストファイルからインポートしたテキストを HTML（Web ページで使われる言語）として扱えます。太字や斜体などの書式付きテキストを、テキストファイルに書き出して再インポートできます。HTML 書式を含めるには、インポート時に **Allow HTML in fields** のチェックボックスをオンにします。内容に山かっこやその他の HTML 構文が含まれているカードをインポートする場合は、オフにしてください。

ファイルの書式に HTML を使いながら、山かっこやアンパサンドも含めたい場合は、次のように置き換えます。

| 文字 | 置換後 |
| --- | --- |
| &lt; | `&lt;` |
| &gt; | `&gt;` |
| &amp; | `&amp;` |

## メディアをインポートする

テキストファイルのインポートに音声や画像を含める場合は、ファイルを[コレクションの `collection.media` フォルダー](../files)にコピーします。**メディアフォルダーにサブフォルダーを作らないでください。一部の機能が動作しなくなります。**

ファイルをコピーしたら、テキストファイル内のフィールドの1つを次のように変更します。

```text
    <img src="myimage.jpg">
```

または

```text
    [sound:myaudio.mp3]
```

代わりに、ブラウザー画面の[検索と置換](../browsing)機能を使って、すべてのフィールドをまとめて更新できます。各フィールドに `myaudio` のようなテキストが含まれ、音声を再生させたい場合は、**正規表現**オプションを有効にして、`(.*)` を検索し、`[sound:\1.mp3]` に置換します。

このような参照を含むテキストファイルをインポートする場合は、**Allow HTML** オプションを有効にしてください。

次のようにテンプレートで指定したくなるかもしれません。

```text
    <img src="{{field name}}">
```

しかし Anki はこの方法に対応していません。使用中のメディアを探すには各カードを描画する必要があり、処理が重くなるためです。また、共有デッキの利用者にとって分かりにくい機能でもあります。代わりに、検索と置換の方法を使ってください。

## 大量のメディア

大量のメディアを一度にインポートする方法として、[メディアインポートアドオン](https://ankiweb.net/shared/info/129299120)もあります。選択したフォルダー内にあるすべてのファイルについて、ファイル名（拡張子を除く。たとえば `apple.jpg` なら表面には「apple」と表示）を表面に、画像や音声を裏面にしたノートを自動作成します。メディアとファイル名の配置を変えたい場合は、作成後に[カードのノートタイプを変更](../browsing)できます。

## 重複と更新

テキストファイルをインポートする際、Anki は最初のフィールドを使ってノートが一意かどうかを判定します。既定では、インポートするファイルの最初のフィールドがコレクション内のノートと一致し、ノートタイプも同じ場合、既存ノートの他のフィールドをインポートしたファイルの内容で更新します。インポート画面のドロップダウンから動作を変更し、重複を完全に無視するか、既存ノートを更新せず新しいノートとしてインポートできます。

**照合範囲**の設定で、重複の判定方法を制御します。**ノートタイプ**を選ぶと、同じノートタイプで最初のフィールドが一致するノートがあれば重複と判定します。**ノートタイプとデッキ**を選ぶと、既存ノートがインポート先のデッキにもある場合に限り、重複と判定します。

更新を有効にしていて、インポートするノートより古いバージョンがすでにコレクションにある場合、そのノートはインポートダイアログで指定したデッキに移動せず、現在のデッキに残ったまま更新されます。既存の場所でノートが更新される場合、そのカードに設定されているスケジュール情報は保持されます。

`.apkg` ファイルの重複処理については、[デッキパッケージ](../exporting#packaged-decks)のセクションをご覧ください。

## ファイルヘッダー

Anki 2.1.54 以降では、インポートをより柔軟または便利にする特定のヘッダーをテキストファイルに含められます。ヘッダーは `#key:value` のペアで、ファイルの先頭に1行ずつ記述します。

| キー | 設定できる値 | 動作 |
| --- | --- | --- |
| `separator` | `Comma`、`Semicolon`、`Tab`、`Space`、`Pipe`、`Colon`、または対応する文字そのもの | フィールド区切り文字を指定します。 |
| `html` | `true`、`false` | ファイルを HTML として扱うかどうかを指定します。 |
| `tags` | スペース区切りのタグ一覧 | インポートするすべてのノートに指定したタグを追加します。 |
| `columns` | 先に設定した区切り文字で分けた名前の一覧 | 列数を指定し、インポート時に列名を表示します。 |
| `notetype` | ノートタイプ名または ID | 存在する場合、ノートタイプをあらかじめ選択します。 |
| `deck` | デッキ名または ID | 存在する場合、デッキをあらかじめ選択します。 |
| `notetype column` | `1`、`2`、`3`、... | 各ノートのノートタイプ名または ID が含まれる列を指定します。[ノートタイプ列](./#notetype-column)を参照してください。 |
| `deck column` | `1`、`2`、`3`、... | 各ノートのデッキ名または ID が含まれる列を指定します。[デッキ列](./#deck-column)を参照してください。 |
| `tags column` | `1`、`2`、`3`、... | 各ノートのタグが含まれる列を指定します。 |
| `guid column` | `1`、`2`、`3`、... | 各ノートの GUID が含まれる列を指定します。[GUID 列](./#guid-column)を参照してください。 |

一部のヘッダーには、追加の動作があります。

### ノートタイプ列

通常、ファイル内のノートはすべて1つのノートタイプに割り当てられます。ノートタイプ名または ID を含む列がある場合は異なります。

この列を使うと、異なるノートタイプのノートをインポートでき、フィールドも自動的に対応付けられます。通常の最初の列は、ノートタイプにかかわらず各ノートタイプの最初のフィールドに使われ、2番目の列は2番目のフィールドに使われます。ここでいう「通常の列」とは、デッキ、タグ、ノートタイプ、GUID などの特殊な情報を含まない列です。

### デッキ列

通常、テキストファイルのインポートで新たに作成されるカードは、選択した1つのデッキに入ります。ただし、ファイルにデッキ列がある場合は、そのノートに指定されたデッキへ新しいカードが入ります。デッキが存在しない場合は、指定された名前で作成されます。

### GUID 列

GUID は _Globally Unique Identifier_（グローバル一意識別子）の略です。Anki でノートを作成すると、一意な ID が割り当てられ、重複の判定に使われます。GUID を含めてノートを書き出した場合、GUID フィールドを変更しなければ、ノートを編集して再インポートし、既存のノートを更新できます。

GUID は Anki が作成することを前提としています。`MYNOTE0001` のような独自 ID を作成する場合は、Anki 内部の GUID に割り当てず、最初のフィールドに置くことをおすすめします。Anki は重複判定に最初のフィールドまたは GUID を使えるため、ノートを更新するために独自 ID を GUID にする必要はありません。

GUID が空でない行には、重複オプションが適用されない点にも注意してください。GUID が指定され、それがコレクション内にすでに存在する場合、新しい重複ノートは作成されません。
